# Creative Strategy: Ideation Package (v3)

A self-contained onboarding package that turns Runneth into a creative-strategy ideation partner for a single brand. It captures how *you* come up with ad ideas, builds reusable banks from your real ad evidence, and then produces full ad concepts on demand.

This v3 is scoped to **ideation only**. The other flywheel stages are named so you see the whole loop, but only ideation is live. Everything here is authored to be brand-agnostic: the sophistication gate branches the experience for experts and beginners, `02` holds the default engine every brand starts from, and the bank-building process works for any brand with a connected Motion workspace. An expert brand's engine gets reconfigured to match how they actually think and saved in that brand's own workspace folder, never edited into this package.

## How to use it

1. Confirm naming conventions first if they were not already confirmed in the workspace's Meta account context (per `05`). Bank building depends on them.
2. Run the 17-question interview (`03`). This captures the team's process and detects their sophistication path (`04`). Questions a VoC audit can already answer get attempted from the audit first, then confirmed, not asked cold.
3. Configure the engine order in `02` to match how the team actually thinks. Starting-out brands keep the default as-is.
4. Build this workspace's three banks from its real ad library using the process in `05`. Confirm every entry with the team per `06`; never reuse another workspace's evidence.
5. Run a Voice of Customer audit to feed the micro-moment step with real customer language.
6. Set up the weekly nominations routine so new winners feed back into the banks automatically.
7. Ask for a concept. The engine runs the full chain and produces a grounded, traceable concept, presented on its own, with execution options offered separately.
8. Tell Runneth what was off. That feedback tightens the engine.

## The one dependency

The engine anchors every idea on customer insight. The richer your real voice-of-customer input (reviews, comments, support messages, social listening), the sharper the output. With nothing, it still runs, but it leans generic. Bring real customer language to the interview if you have it.

## What changed from v2

- Default engine in `02` restored to brand-agnostic. It had drifted into one early test brand's specific reconfigured order (awareness stage moved up, a two-bucket persona system, an explicit Benefit step).
- No standalone Benefit step in the default. The outcome someone wants is part of how the persona is described, not its own numbered decision.
- `07`'s required-fields table matches the restored default engine, with a note that a reconfigured expert engine uses its own fields instead.
- New presentation rule: concept first, execution options in a separate "ways to bring it to life" section, source trace collapsed or on request.
- New prerequisite in `03`: use a VoC audit for VoC-answerable questions, but confirm, don't assume.
- New prerequisite in `05`: confirm naming conventions before reading product tags from ad names, using the account context if it is already confirmed.

## What changed from v1

- 17 questions instead of 30
- 3 banks instead of 4 (messaging strategies removed; angle is derived, not banked)
- Banks built from real ad evidence instead of interview recall
- Corrected stack order (mechanic before hook)
- Concept vs. execution split
- Research as an active, ongoing step
- Weekly nominations routine as standard setup
- Standing rules: video vs static stated, images verified, "Other" resolved
