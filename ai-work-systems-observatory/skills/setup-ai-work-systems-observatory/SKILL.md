# Setup AI Work Systems Observatory

## 1. Frame the output

Explain that this creates an executive report, not an activity dashboard. It will show how the team operates today, which systems are proven current systems, and which systems are recommendations.

## 2. Propose exact access and writes

List the organization, date window, inventory sources, bounded conversation-search scope, files to write, private app to create, and any optional routine. Installation is not approval. Ask once for explicit approval.

## 3. Collect inventory evidence

Run the deterministic collector. Inventory is classified as available capabilities, delivered assets, incomplete setup, or recurring mechanisms. It does not create current systems.

## 4. Reconstruct the operating model

Using the smallest approved sources, map:

- roles and responsibilities
- recurring meetings, decisions, and cadence
- handoffs and approval gates
- repeated manual coordination and friction
- outputs people review, approve, or act on
- weekly and monthly operating rhythms

When inventory cannot establish job, owner, audience, output, or consumption, run the already-approved bounded conversation search. Keep findings as facts, inferences, or unknowns. If one decisive fact remains unresolved, ask one focused follow-up.

## 5. Qualify current systems

Promote a recurring mechanism only when the observed ledger has a confirmed owner with direct evidence, a real trigger, identifiable input and output, observed consumption, run-health evidence with a visible window, human control, confidence, and last-confirmed time. Otherwise keep it outside current systems with explicit qualification gaps.

## 6. Define adoption

Use qualified-system consumption coverage. Record the population, rule, numerator, denominator, and evidence. Never substitute conversation participation or ownership coverage.

## 7. Synthesize the proposed model

Answer the six synthesis questions in the executive report contract. Recommend three to five proposed systems, role changes, the weekly cadence, top three opportunities, and phased sequence. Label every recommendation and link it to evidence or a hypothesis.

## 8. Validate and render

Validate `system-ledger.json`, `operating-model.json`, and `observatory.json`. Create the app from the package template, keep Motion authentication enabled, build, verify, and hand back the ready app.

## 9. Review before recurrence

Check the six regression answers with the requester. Offer a refresh routine only after the first report is accepted. Routine creation requires its own confirmed delivery and schedule.
