# 05: Library Confirmation Gate

Nothing enters this library without a human yes. This is a hard rule, at every moment
the library could grow.

## When the gate fires

1. **At setup**, when the bank-building process (`04-bank-building-process.md`)
   proposes seed entries built from this account's real ad library, including the
   universal-checklist and newly-discovered creative mechanics Step 5 finds.
2. **On every submission**, when a new asset gets classified (`01`, Steps 1-5) into
   an existing tag or a proposed new one.
3. **Over time**, if this account ever adds a scheduled review of the swipe-file
   library, when a pattern crosses from candidate to confirmed per
   `02-pattern-library-and-concept-use.md` Step 3.

## What the gate looks like at setup

**Table format, one table per axis, not a bullet list.** Every seeded candidate goes
into a real markdown table, grouped under a bold axis heading. This is a preset shape,
use it every time this gate fires at setup, not only when someone asks for a table:

**Hook Tactics** (or **Headline Tactics** for the written side)

| Tactic | Verbatim | Visual |
|---|---|---|
| [tactic name] | [exact quote, not paraphrased] | [what's on screen while it plays] |

**Visual Formats**

| Format | What it is | Evidence |
|---|---|---|
| [format name] | [the shape, one line] | [creative count, spend, or the tested example] |

**Creative Mechanics** (name the population and any naming-tag convention this
account uses, when known, right after the heading, the same way the other axes get
their real counts)

| Mechanic | The move (subject stripped out) | Verbatim proof |
|---|---|---|
| [mechanic name] | [the cognitive move, generalized past the specific subject] | [exact quote or on-screen line proving it] |

**The verbatim/proof column is never paraphrased.** Copy the exact line from the
source, quotation marks included. A summary of what someone said is not a substitute
for what they actually said.

Close every setup confirmation the same way, after the tables:

> This lives at [the account's swipe-file library path], separate from your tested-ad
> library. Add these? You can approve all, approve per axis, or strike any single one.

## What the gate looks like on an ongoing submission

One entry at a time, plain language. For link submissions the evidence trail always
names the exact source URL, never just the platform or creator handle; for directly
uploaded files the upload is itself the evidence - name the platform and handle when
known, and never hold the entry hostage to a URL that doesn't exist.

**Verbatim/visual on an ongoing submission is the specific applied excerpt, not a
full transcript.** Quote the exact moment or line that shows the axis in action, and
describe how just that moment is delivered, not a shot-by-shot retelling of the whole
asset.

Use this shape for the proposal, one field per line, a blank line between each field,
never run together in one paragraph:

> <axis emoji> **<Axis>** -> [existing tag name, or a proposed new candidate name]
>
> **The shape:** (visual format) / **The move:** (creative mechanic) / **Pattern:**
> (hook/headline tactic) - the generalized, subject-stripped definition.
>
> **Applied here:** the specific excerpt from this asset that demonstrates it, not a
> recap of the whole asset.
>
> **Index row:** *[short name]*, the one-line index description.
>
> **Taste note:** the personal reason this asset triggered the save.
>
> **Evidence:** the exact source URL for a link, or "direct upload" plus platform/
> creator handle when known, for an uploaded file.
>
> Add it?

This spaced-out shape (one field per line, blank line between fields) is the default
for every proposal going forward, not a per-conversation formatting choice. It is the
chat-confirmation shape only; it does not govern how the swipe-file app renders a
card, see `06-swipe-file-app.md` for that surface's own, deliberately lighter shape.

## Approval modes

- **Approve all**: everything shown is saved.
- **Approve per axis**: say yes to some axes, hold others, useful at setup when one
  axis's seed set looks stronger than another's.
- **Strike one**: remove any single candidate before saving the rest.

Default is per-axis approval at setup, and per-entry approval on ongoing submissions,
so one bad candidate never forces a reject on an otherwise good batch.

## Why the gate exists

This library is meant to reflect this account's actual taste and real evidence, not
become a dumping ground. If junk gets in silently, whether from a bad seed pull or a
misclassified submission, it quietly degrades every future concept pulled from it.
The gate is what keeps that from happening.
